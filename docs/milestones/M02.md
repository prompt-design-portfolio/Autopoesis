### Two backends, one set of logic (§6, §43)

Three dialect seams, each behind a type decorator or a single function: JSON (`JSONB` vs. text),
UUID (native vs. 32-char hex), timestamps (SQLite discards tzinfo, so `UTCDateTime` normalises both
ways), vectors (pgvector vs. exact float32 blob), and job claiming (`FOR UPDATE SKIP LOCKED` vs.
compare-and-set). Nothing above `civitas/persistence` branches on dialect.

SQLite gets WAL, `foreign_keys=ON` — off by default, which would have made every `ondelete` clause
decoration — a busy timeout, and `BEGIN IMMEDIATE`. That last one matters: SQLAlchemy's deferred
BEGIN turns read-then-update leasing into a mid-transaction `SQLITE_BUSY`.

**The whole suite runs against both backends.** `CIVITAS_TEST_POSTGRES_URL` adds a PostgreSQL
parametrisation to every test; unset, the suite runs on SQLite alone and says so rather than
silently testing one backend while claiming two. This milestone's results are from 57 tests across
both.

## Three defects the tests found

Recorded because Part A §A1.4 asks tests to drive the real mechanism, and these are what that
bought:

1. **Enum columns round-tripped as bare strings.** `String(32)` returns `str`, so
   `episode.experiment_arm.value` would have raised at a call site far from the model — and the
   arms are machine-enforced (§21), so enforcement code has to be able to trust the type it gets
   back. Fixed with an `EnumType` decorator that returns members, and that tolerates an unknown
   value by returning the raw string rather than making an old experiment record unreadable (§46).
2. **Four models documented themselves as append-only without being marked `Immutable`.**
   `ArtifactUtilityMetric` was the consequential one: `Artifact.downstream_utility` is a *fold* over
   those rows (Part A §A2.1), so an editable credit event would let utility be inflated after the
   fact and the fold would not be reproducible. `ArtifactVersion`, `ReputationMetric` and
   `ExperimentManifest` were the others. `ToolVersion` went the other way — its source is
   write-once but validation state legitimately changes after testing, so the docstring was
   corrected instead of the class.
3. **A concurrency race that only PostgreSQL exposed.** `_next_sequence` did `SELECT … else
   INSERT` on the counter row. Under contention two transactions both see no row and both insert;
   the second gets a unique violation. SQLite never showed it, because `BEGIN IMMEDIATE`
   serialises the whole transaction. Fixed with `ON CONFLICT DO NOTHING`, which both dialects have
   supported for years, so the two backends take the same code path.

Defect 3 is the argument for the two-backend parametrisation in one example: on SQLite alone the
test passed, and the event stream — the thing the entire reconstructability claim rests on — would
have dropped events in production.
