## The headline: an honest null, and the instrument that explains it

M5's obligation under Part A §A3 is to re-report the M4 benchmark so the knowledge system's
contribution is measured rather than assumed. Run as a matched A/B — same task family, same
seeds, same budgets, same agents, one variable moved:

| | `retrieval/1.0-lexical` | `retrieval/2.0-hybrid` | delta |
|---|---|---|---|
| newcomer advantage | 0.300 | 0.300 | **0.000** |
| advantage lost to reset | 0.300 | 0.300 | 0.000 |
| advantage lost to scramble | 0.300 | 0.300 | 0.000 |
| collective mean probes | 0.27 | 0.33 | +0.07 |

**The hybrid retrieval moved nothing.** Reported here rather than buried, per Part A §A1.5.

That is not evidence the components do nothing. It is evidence the newcomer benchmark **cannot
see them**, and the reason is identifiable: its corpus is a few dozen artifacts, and its queries
contain the exact rare token that names the target (`belnor`), so BM25 already ranks the right
artifact first. There is no rank left to improve. An instrument that cannot resolve an effect must
not be reported as having found its absence.

So M5 built the instrument that can. `retrieval_benchmark.py` measures rank quality directly
against a 306-artifact corpus, under two query conditions:

| policy / condition | MRR | recall@1 | recall@3 |
|---|---|---|---|
| lexical / exact | 1.000 | 1.000 | 1.000 |
| hybrid / exact | 1.000 | 1.000 | 1.000 |
| lexical / **paraphrase** | 0.297 | **0.000** | 0.333 |
| hybrid / **paraphrase** | **0.486** | **0.167** | **0.833** |

On exact queries the two are identical and both perfect — which *is* the explanation for the null.
On paraphrases, where the query shares **no content word** with its target (asserted by a test, and
it caught two leaks while being written), the lexical ranker never puts the target first, and the
hybrid ranker raises MRR by 64% and recall@3 from 0.333 to 0.833.

Paraphrase is not the artificial condition. It is what an agent produces when it does not already
know the answer's vocabulary — which is the situation the collective exists to help with.

**Consequence for the plan.** The newcomer benchmark measures whether the collective *transmits*;
it does not measure retrieval quality. M9's benchmark families need a corpus large and noisy
enough that ranking is load-bearing, or later retrieval work will keep reporting nulls that mean
nothing.

## What each component is, and the decision inside it

### Embeddings (§14, §43)

`HashingEmbedder` — deterministic character-n-grams plus whole words. Not a stand-in for a learned
model: it is a real, blunt semantic index with a property a hosted model cannot offer, which is
that it **cannot be revised underneath a campaign**. A benchmark whose entire claim rests on the
individual agent being frozen (§20) cannot depend on an embedding endpoint that may change without
telling it. `ProviderEmbedder` is the complete hosted adapter, mocked in tests.

Vectors are keyed by `(artifact, model)`, so re-embedding under a new model adds a row rather than
overwriting — retrieval computed under an older model stays reproducible (§46).

Indexing happens at **artifact creation**, not lazily at retrieval. Retrieval is a read path;
indexing there would make every search a write and give every ablation arm the ability to mutate
the workspace it is meant to be observing.

### Hybrid retrieval (§14)

All of §14's components are now present and each is recorded as a named feature on the
`RetrievalDecision`: vector, lexical (BM25-shaped), graph proximity, task relevance, recency,
confidence, validation, provenance strength, environment applicability, negative-knowledge
relevance, diversity and contradiction exposure.

Vector similarity is weighted **below** lexical, because for agent-written artifacts an exact term
match is the stronger signal and §14 forbids relying on embeddings alone. Semantic search is
restricted to the candidate set the arm already allowed — the vector index must never be a way
around an ablation (§21), and a test asserts it is not.

### Two §14 requirements that were prose and are now mechanisms

**"A retrieval result should avoid ten nearly identical artifacts."** The first implementation
penalised overlap. That does not work, and the test proved it: a penalty is subtracted *equally*
from every member of a set of duplicates, so their relative order is unchanged and all of them are
still selected. Measured on twelve identical artifacts, it returned five identical results.
`_diversify` now hard-skips anything above 0.85 overlap with something already chosen, and holds
near-duplicates back to fill the limit only if nothing distinct remains — returning fewer results
than asked for would be the worse failure, because a caller cannot distinguish "nothing else
matched" from "the ranker suppressed it".

**"Agents should sometimes be deliberately shown relevant disagreement."** A pure relevance
ranking systematically removes the artifact most likely to correct the top result, because a
contradiction of a strong match is usually a weaker match itself. `_expose_contradictions`
displaces the lowest-ranked selection rather than growing the set, so what an agent sees changes
without changing how much it sees.

**"Prior failures should receive increased relevance."** The first gate here also failed a test:
it triggered on embedding similarity above 0.2, and a hashing embedder assigns moderate similarity
to any two pieces of English prose — a failure about cache eviction scored 0.3 against a query
about lock retries. Aboutness now requires a shared term, with a much higher bar for semantic-only
matches. A blanket boost for negative types is a reliable way to make agents ignore them.

### Provenance (§13)

`graph.provenance()` returns the chain, **and what challenges it**. A record that shows only what
supports a claim is an argument, not a record (§11). `grounding_score` takes the strongest evidence
in the chain discounted by distance — deliberately not an average, because one reproduced result
grounds a claim and averaging it against nine assertions would hide that.

Traversal is depth-capped with a visited set. Both are load-bearing: an agent-built graph can
contain cycles, and `graph_distance` returns `None` beyond its search depth rather than a large
number, because "further than we looked" is not "far".

### Versioning (§9)

The snapshot is taken *before* mutation. Taking it after would record the new state twice and lose
the old one — a silent overwrite dressed as versioning. Version rows are append-only, enforced by
the M2 session guard.

Supersession is kept distinct from editing: editing says an artifact now says something else;
supersession says a *different* artifact replaces it, and keeps both readable and both
attributable. `resolve_head` is hop-capped, because a supersession cycle is constructible.

### Staleness (§15)

§15's requirement is precise: *a stale artifact should not disappear; it should be visibly stale.*
So nothing here deletes, archives or hides. Staleness is a flag retrieval penalises and a reader
can see, and it is **reversible** — one-way staleness would slowly condemn a whole workspace with
no way back.

Invalidation cascades as *staleness*, not as refutation. A conclusion resting on a refuted premise
is unsupported, not thereby false; it needs re-examination, and marking it stale says exactly that.
A test asserts the dependent conclusion is not marked `REFUTED` by association.

### Consolidation (§16)

Every operation is additive or reversible, because §16's binding constraint is that source
provenance is never destroyed.

- **Duplicates are linked, not deleted**, and archiving the newer copy is **off by default**: two
  agents independently reaching the same finding is a *replication*, which is the strongest signal
  the collective produces, and collapsing it silently would destroy it.
- **Summaries are extractive**, not generated. A model-written summary is an assertion *about*
  evidence, and storing it as a `summary` artifact would quietly upgrade assertion to established
  fact. Summaries carry `INFERENCE` provenance and `UNVALIDATED` state even when every member is
  evaluator-confirmed — a test asserts this.
- **Contradiction detection records candidates, not verdicts**, with `INFERENCE` provenance, for an
  agent to confirm. A real entailment check needs a model, and calling a model's opinion a detected
  contradiction is exactly the unearned upgrade §11 warns about.
- The **duplicate threshold is bracketed and its distribution reported**, so it is checkable
  against a real corpus rather than asserted.

## Effect on the M4 benchmark

**None**, measured as a matched A/B, and explained above. The knowledge system's measurable
contribution is on rank quality under paraphrase queries: MRR 0.297 → 0.486, recall@3 0.333 →
0.833. Both numbers are committed in `results/m5_knowledge_system.json`.
