## The headline measurement

Five seeds, six classes per seed, **n = 30 probe episodes per arm**, one configuration hash across
all four arms. Full data in `results/m4_newcomer_benchmark.json`.

| arm | success rate | mean tool calls | mean probes | artifacts read | duplicate failures |
|---|---|---|---|---|---|
| `baseline_empty` | 0.467 | 6.07 | 4.60 | 0.00 | 0 |
| **`collective`** | **0.767** | 4.37 | **0.27** | 1.47 | 26 |
| `memory_reset` | 0.467 | 6.07 | 4.60 | 0.00 | 0 |
| `collective_scrambled` | 0.500 | 5.87 | 2.53 | 1.83 | 38 |

Chance level 0.100. All four gates pass.

- **newcomer advantage +0.300**
- **`memory_reset` removes 100% of it**
- **`collective_scrambled` removes 89% of it**

That is §22's primary criterion met: a fresh unchanged agent performs substantially better inside
the mature collective, and the advantage largely disappears when the accumulated information is
removed or scrambled. The scramble control matters more than the reset: it holds the *quantity*
of artifacts fixed and destroys only their relevance, so it separates "information passed" from
"a store existed" — the `noise record` lesson from this repository's own research lineage.

The probe count is the sharper instrument: 4.60 → 0.27, a seventeen-fold reduction. Success rate
saturates; cost-to-solution does not, and both are reported for that reason.

## The task family, and why this one

`civitas/experiments/tasks/hidden_rule.py`. A device holds a hidden bijection from input classes to
operations; an episode discovers it by probing, one probe per tool call, against a hard budget.
Three properties, taken directly from the research lineage:

1. **Objectively evaluable (§47).** The true mapping is known to the evaluator and to nothing an
   agent can read. The task description offers every operation identically, so a reader of the
   brief can do no better than chance.
2. **The mapping and the surface labels both rotate between eras.** This is `π`. Rotating the
   mapping alone would leave the labels as a stable index a collective could key on. With both
   rotating, an artifact from a previous era describes a device that no longer exists — so a
   collective that appears to help *by recall* is caught, and stale-artifact usage becomes
   measurable (§15, §48).
3. **Structure survives what facts do not.** The mapping is a bijection, so ruling out an operation
   for one class constrains every other class. Without that, nothing would transfer across an era
   boundary and the collective would be pointless; with it, what transfers has to be understood
   rather than copied.

### The agent is a deterministic policy, and that is the point

`PolicyAgentProvider` is a pure function of what it is shown. Frozen-model mode (§20) asks that
individual variables be held constant; a deterministic policy takes that to its limit, so any
difference between arms is caused by what the arms showed the agent — not by sampling, not by
temperature, not by a model revision. A frozen LLM can only support that claim statistically.

It is also honest about what it measures: **the platform's contribution, not a model's
intelligence.** The same benchmark runs against any provider in §19, and the manifest records
which produced a given result.

## Five defects, each found by measuring rather than assuming

This is the milestone's real content. Each was found by reading a number that did not make sense
and chasing it, which is the discipline `analysis_v3_13.py` encodes.

### 1. Credit assignment was inert in the only benchmark that exercises it

`ArtifactUsage` links were **zero** after a full run, so §A2.1 had nothing to propagate along.
Cause: `search_knowledge` returned artifact *bodies*, so an agent never needed `read_artifact` and
nothing was ever recorded as read.

Search now returns identities and titles only. That fix is load-bearing twice over: credit needs a
real read to attach to, and **ranking only means something when reading is rationed**. An episode
that can read two of eight results makes rank consequential — which is what makes
`collective_scrambled` an actual control rather than a reshuffle of a list the agent was going to
consume in full anyway.

### 2. The success-rate instrument did not discriminate, and the equality was structural

Across five different budgets, `collective` matched `baseline_empty` **to three decimal places**
while halving probe count. Too exact to be noise.

Cause: every agent probed operations in one fixed order. So the operations a failed predecessor
ruled out were exactly the prefix its successor would have tried first — negative knowledge saved
tool calls while carrying no information about *where* the answer was. Real agents differ;
modelling them as identical makes §12's negative knowledge worthless by construction.

Probe order is now varied per agent, seeded from `(seed, class, pass)` and **never from the arm**,
so every arm faces the same sequence of agents and the comparison stays matched.

### 3. The benchmark was irreproducible between processes

`_order_seed` used Python's `hash()`, which is randomised per process unless `PYTHONHASHSEED` is
set. A benchmark whose agents differ between invocations cannot support any claim about what
changed (§46). Now `hashlib`, and reproducibility across separate processes is asserted.

### 4. Duplicate-failure detection was structurally unable to fire

`duplicate_failure_rate` is a *primary* metric (§12, §48) and it read 0.000 in every arm — not
because agents never repeated work, but because nothing in the task family ever registered a
documented failure with a tool key. A rejected probe is precisely a documented failure of that
exact call, and it now registers as one. Detection runs in every arm (it is the measurement); only
surfacing is arm-gated (it is the intervention).

Wiring it also exposed that `memory_reset` archived artifacts while leaving the duplicate index
answering — the arm would have kept the one thing it exists to lose. Failure records are now
retired alongside the artifacts.

### 5. The duplicate mechanism was killing the episodes it was built to help

After wiring §A2.3 the advantage **fell from +0.300 to +0.200**. Chasing it: 4 of 5 collective-arm
failures terminated with `no_progress` at 4.6 tool calls of a 7 budget — with budget unspent.

Cause: a blocked duplicate never set `made_progress`, so a run of successfully-avoided repeats
counted as consecutive no-progress turns. Being told "this was already tried and it failed" is
information the episode did not have a moment ago. One line, and the advantage returned to +0.300
*with* duplicate detection live. A second bug surfaced alongside it: repeated warnings about one
artifact violated `ArtifactUsage`'s uniqueness key.

Both numbers are reported here rather than only the good one. A feature that cost a third of the
headline until a bug was found is worth knowing about.

## A security finding: a limit that was not enforced

`RLIMIT_NPROC` **is not enforced for uid 0**. Against `max_processes=8`, a sandboxed loop performed
5000 sequential forks in under a second while the suite ran as root. A bound the caller believes is
in force but is not is worse than no bound, because it gets relied on.

The sandbox now *declares* it: `Sandbox.unenforced_limits()` reports `max_processes` under uid 0,
the value reaches `SandboxResult` and the manifest, and a test asserts the declaration is accurate.
The wall clock and the process-group kill still contain such a tool, so the sandbox is not
defeated — but the process bound is advisory there, and the container backend does not have the
problem at all, because cgroups enforce `--pids-limit` regardless of uid.

Found while fixing a related test-hygiene defect: a genuine recursive fork bomb transiently
exhausted the host process table and made three unrelated tests fail to `fork()`. A test that
destabilises its neighbours is measuring the harness, not the sandbox.

## The difficulty setting was measured, not chosen

A benchmark tuned until it produced an advantage, with the tuning unreported, is indistinguishable
from one that found an advantage. The sweep is committed in
`results/m4_newcomer_benchmark.json`:

| tool calls | baseline | collective | advantage | gates |
|---|---|---|---|---|
| 5 | 0.300 | 0.467 | +0.167 | pass |
| 6 | 0.333 | 0.633 | +0.300 | pass |
| **7** | **0.467** | **0.767** | **+0.300** | pass |
| 9 | 0.700 | 0.767 | +0.067 | pass |
| 12 | 1.000 | 1.000 | 0.000 | **FAIL — baseline at ceiling** |

At 5 the budget is too tight for a fresh agent to exploit what it reads; at 12 the baseline
saturates and there is no headroom, which the `baseline_has_headroom` gate catches and withholds
the row for. Seven is where the instrument discriminates.

## Gates precede rows

Four prerequisites, checked before any number is reported. `BenchmarkResult.metrics()` **raises**
when a gate fails; a caller wanting to diagnose must call `raw_metrics()` and thereby say in the
code that it is reading an unlicensed number.

| gate | what it protects against |
|---|---|
| `frozen_model` | arms running under different configurations, making the comparison unmatched |
| `accumulation_occurred` | `collective` and `baseline_empty` being the same condition, which would make a null uninterpretable |
| `baseline_has_headroom` | a saturated baseline, where no advantage is measurable |
| `sufficient_n` | a rate read off too few episodes to mean anything |

## Metrics exposed (§48)

`civitas/experiments/metrics.py` computes success rate, tokens/cost/tool-calls/time to solution,
artifact count and survival, negative-knowledge share, stale-artifact share, knowledge reuse,
duplicate-failure rate, provenance edges and depth, validated share, artifact utility, tool reuse
and success, retrieval statistics, and confidence calibration.

Metrics that need a mechanism not yet built — specialization index, capability frontier, cumulative
improvement, retrieval precision — return `None` **with a stated reason**, never 0.0.
