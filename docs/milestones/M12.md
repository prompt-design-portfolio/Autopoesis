## The starting point: four settings that did nothing

`log_json`, `metrics_enabled`, `otel_endpoint` and `rate_limit_per_minute` have been in
`Settings` since M1. Every one was read from the environment, printed into the manifest, and then
read by no code at all. That is worse than not having them: it tells an operator a control exists.

This is the same shape as M10's `civitas` entry point — declared in `pyproject.toml`, pointing at
a module that did not exist. Both were found by looking for the gap between what the configuration
promises and what the code does.

## The measurement: what a circuit breaker saves during an outage

Retry with backoff already existed (`http.py`, four attempts, jittered exponential). On its own it
makes an outage **more** expensive: every episode pays four network attempts and up to thirty
seconds of sleep to re-learn what the previous episode established.

Forty episodes against a provider that is down, one variable — the breaker:

| | no breaker | breaker |
|---|---|---|
| episodes | 40 | 40 |
| provider calls attempted | 40 | **3** |
| calls skipped by the breaker | 0 | 37 |
| episodes terminated `provider_failure` | 40 | 40 |
| derived network attempts | 160 | **12** |
| derived worst-case backoff | 210 s | **15.8 s** |

**92.5% of provider attempts avoided.** The derived rows are labelled derived: they are computed
from `http.MAX_RETRIES` and the documented backoff schedule, not observed, because the offline
provider used here does not sleep and reporting a wall-clock saving it never paid would be
inventing a measurement.

The last row of the table is the one that matters for the science. **Every episode in both arms
still terminates as `provider_failure`**, which `evaluation.is_readable` already excludes from
success rates (§47). The breaker changes what an outage costs; it does not change what any arm
scores. An outage counted as an agent's failure would let infrastructure noise masquerade as a
weaker arm, and that is exactly what the breaker must not introduce while preventing.

## §52 — security controls

- **CSP written against the UI, not copied from a guide.** `civitas/web/` loads one script and one
  stylesheet from its own origin and opens an `EventSource` to its own origin. So
  `default-src 'self'` with no `unsafe-inline` is a *description* of the page, not a restriction it
  works around. The one exception — Swagger UI's CDN — is explicit and scoped to scripts and
  styles. A browser test renders the page under the real header and asserts the browser reported
  no violation, because a CSP is trivial to get wrong in a way no unit test sees: the header is
  present, the assertion passes, and the page is silently broken.
- **Secret redaction on the rendered message.** A filter that inspected `record.args` would miss
  `log.error("failed: %s", exc)` — which is precisely how a key in an exception string reaches a
  log. The pattern set was extended after a test caught it missing the JSON form
  (`"api_key": "..."`), which is the shape secrets most often arrive in.
- **Rate limiting**, sliding-window, keyed on the API key's *prefix* rather than the key — the
  limiter's state is readable in a heap dump. `/healthz` and `/readyz` are exempt: a limiter that
  can make a load balancer believe the process is unhealthy turns a traffic spike into an outage.
- **Body size limit** refused on the declared length, before the body is read.

The limiter is in-process. Two replicas allow twice the configured rate. That is stated in the
class docstring, reported by `/healthz` as `rate_limit_is_per_process: true`, and not papered
over — the fix is a shared store, and inventing one here would be a larger claim than this
milestone supports.

## §53 — observability

Structured JSON logging with a correlation id per request, echoed as `x-request-id` and accepted
from the client so a caller can find its own request. A Prometheus endpoint at `/metrics`.

**The registry is written here rather than imported.** `prometheus_client` is not a dependency,
and adding one to expose a dozen counters would make an air-gapped or Colab install (§33, §34)
depend on a package it cannot fetch. The exposition format is documented text; the parts this
needs are a hundred lines.

Two disciplines carry over from the rest of the platform:

- **A counter never incremented reports `None`, not `0.0`** (ARCHITECTURE §3.9). "Nothing
  happened" and "we have no data" are different facts, and only the exposition format may flatten
  them.
- **Labels are route templates, arms and providers — never ids.** A label whose value is an id
  gives the metric unbounded cardinality, which is how a monitoring system is taken down by the
  thing it monitors. A test asserts no workspace id reaches `/metrics`, which is also the easiest
  place to leak a tenant list.

Tracing degrades and metrics do not: with OpenTelemetry absent, `span()` is a no-op and `/metrics`
still reports everything. `configure_tracing` returns its state and `/healthz` publishes it, so
"configured but the package is missing" is visible before an incident rather than during one.

## §58 — resource management

§39 bounds one episode. Nothing bounded *many*: a scheduler that keeps finding ready work keeps
spending, and every episode is individually within budget while the organization's month is not.

Quotas are computed from the same `Episode` rows the cost dashboard reads — no running total,
because a counter that drifts from the episodes it summarises is a quota that either blocks work
that never happened or allows work that did. Benchmark probes count: excluding them would let a
campaign spend an organization's month while the quota report showed it idle.

The check runs in `EpisodeRunner.run` **before the episode row is created**. Ordering matters
here in a way that is easy to get backwards: a row created and then refused would be counted by
the very usage query the quota is measured with, so exceeding a quota would raise the usage that
proves it was exceeded.

An organization with no quota is unlimited, and `remaining()` reports `None` rather than a large
number — a dashboard cannot render "no limit" as "nearly out". A zero or negative limit is
ignored rather than treated as "block everything": it is almost always a typo, and a quota that
silently halts an organization is worse than one that is visible in the report.

## §56, §57 — CI and deployment

`.github/workflows/ci.yml` runs five jobs: lint, the **two-backend** test suite, a migrations job
that checks `alembic upgrade head` agrees with the models, the browser tests as their own job (so
a missing browser is a visible skip rather than a silent hole in another job's count), and an
image build.

The image job asserts the container does not run as uid 0. That is not a formality: M4 measured
`RLIMIT_NPROC` being **silently unenforced for root** — a test spawned 5000 processes against a
limit of 8 — and `Sandbox.unenforced_limits()` exists to report it. An image running as root
would advertise sandbox limits it does not hold.

`ops/Dockerfile` (two-stage, non-root, `HEALTHCHECK` on `/readyz` rather than `/healthz`, because
a container answering "the process is up" while its database is gone keeps taking traffic it
cannot serve), `ops/docker-compose.yml` (Postgres, a migrate job, API, worker — API and worker
share one image, since two would be the separate implementation §6 forbids), and
`ops/k8s/civitas.yaml` (migrations as a pre-roll Job so replicas do not race the same schema
change; liveness on `/healthz` and readiness on `/readyz`, because using readiness for liveness
restarts every replica during a database blip and turns a recoverable outage into a crash loop).

## Defects found

1. **The histogram double-counted its own buckets.** `observe` already increments every bucket a
   value falls under, and `render` summed them again — producing a non-monotonic bucket series,
   which is how a histogram reports latencies that never happened. Caught by rendering one
   observation and reading the output.
2. **`opened_at = 0.0` read as "never opened".** `if state.opened_at` is falsy at zero, so a
   breaker opened at the origin of an injected clock reported itself closed — and the injected
   clock is exactly what the tests use, so the field would only ever have been wrong where it was
   being checked. `is not None` throughout.
3. **The breaker reported ages from the wrong clock.** `as_dict` called `time.monotonic()` while
   the breaker used its injected clock.
4. **The redaction pattern missed the JSON form.** `"api_key": "secret"` has a quote between the
   name and the colon; the most common shape was the one slipping through.

## Effect on the newcomer benchmark

**0.000, and expected.** Nothing here changes what an agent sees inside an episode. The one thing
that could have changed a measurement is the quota check, and it is inert by default: an
organization with no configured quota is unlimited, so every existing benchmark runs exactly as
before. The breaker changes what an outage costs, not what any arm scores — stated above and
recorded in the results file.
